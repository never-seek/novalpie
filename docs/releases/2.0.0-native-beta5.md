# NovalPie 原生 Android 2.0 Beta 5

这不是把 NovalPie 网页缩小后塞进 App，也不是另一个书源阅读器。它是以 NovalPie 账号和源站接口为唯一数据来源的 **原生 Android 客户端**：保留网站的内容、权限与积分规则，但针对手机阅读、下载、触控和小屏信息密度重新组织交互。

如果你只是想在手机浏览器里使用完整网页，直接访问网站即可；安装这个 App 的价值在于下面这些网页没有提供、或在手机上体验较差的原生能力。

## App 与网页的核心区别

| 场景 | 网页做法 | App 2.0 的原生差异 |
| --- | --- | --- |
| 页面切换 | 浏览器历史、网页重新渲染 | 五个固定主入口与原生返回栈；快速从 A 返回再打开 B，不复用旧书或旧帖内容。 |
| 阅读 | 网页阅读器和浏览器滚动 | 独立原生阅读器，支持分页、无限滚动、音量键、动画、排版设置、章节状态和系统返回逻辑。 |
| 下载 | 浏览器生成/保存文件 | EPUB/TXT 由 App 直接写入 Android 下载目录，支持原图、并发、暂停、继续、取消和失败重试。 |
| 书架 | 以网页布局展示数据 | 2/3/4 列手机书架、继续阅读、章节进度、更新提醒和触控批量管理。 |
| 图片 | 浏览器按网页资源显示 | 静止长按原图预览，支持放大、拖动、GIF、Animated WebP 与幻影坦克类内层图；滚动不会误触预览。 |
| 论坛内容 | 由网页 HTML/脚本负责 | 原生渲染黑幕、fold、书籍分享卡、Markdown/HTML 图片和嵌套评论，减少“代码裸露”与网页返回栈错乱。 |
| 网络与适配 | 由浏览器决定 | 原生加载/重试状态、模拟器/真机代理策略、输入法恢复、小屏排版和图片预取控制。 |

## 五个主页面：每个页面的 App 特点

### 收藏：不是纯封面墙

- 可选择每行 **2、3、4 本**，同时保留封面、书名、作者和阅读进度；不同标签数量的卡片仍让同行底部指标对齐。
- “继续阅读”显示作品名和章节名，进度以已读章节与最新目录计算，避免未读作品被错误显示为读完。
- 已读完作品出现新章节后，会显示可继续阅读的更新状态。
- 长按书籍进入批量管理，不会在翻页或滑动时误放大封面。
- 书架请求失败有原生重试，恢复后无需网页刷新或重启 App。

### 搜索：把复杂网页筛选变成可保存的手机筛选器

- 未输入关键词时直接加载默认作品，不保留网页式空白结果页。
- 搜索范围、成人区、来源、规则、标签、字数、搜索模式和排序均以源站真实参数请求；筛选偏好可以保留到下次打开。
- 成人区明确区分“所有 / 仅成人 / 全年龄”，不会只改按钮样式而混用结果。
- 高图列表对封面预取做了限制，优先减少快速下滑时的解码掉帧，不以压缩原图来换速度。
- 搜索卡片为标签和三项指标预留统一空间，避免左右两本书因为标签多少不同而底部不齐。

### 工具：把手机常用操作集中起来

- 消息、私信、工作区、上传书籍、EPUB 编辑器、术语表和应用设置由原生路由承载，站内链接能回到相应 App 页面。
- 阅读、搜索、显示与代理偏好以本地设置持久化，不需要反复在网页中调整。
- 管理员账号才会看到管理后台、审核、密钥、操作日志、抓取与商店等入口；普通账号不会因缓存或旧页面误看到管理员功能。
- 网页生成 EPUB 的下载流程不再作为手机主路径，App 的原生下载是默认方案。

### 论坛：不是简单把帖子 HTML 放进浏览器

- 帖子卡、评论树和回复关系由原生状态维护，单次点按可打开，滑动不会误开；返回后再打开另一帖不会显示上一帖内容。
- 支持根评论、回复、回复的回复；失败时保留草稿和回复对象，便于重试。
- 评论输入提供常用源站语法工具：粗体、斜体、标题、引用、代码、链接、列表、下划线、删除线、黑幕和折叠。
- 评论/帖子中的黑幕默认遮挡、单段点按揭示；“显示剧透”偏好同步到论坛、书评、章评和动态。
- `[bookid:...]` 会成为可点开的原生作品卡片，`fold`、长链接、Markdown/HTML 图片、GIF 与 WebP 会按内容组件显示，而非直接露出代码。

### 我的：按手机信息层级重排资料与装扮

- 个人资料、头像框、已装备 badge、动态、上传书籍和公开主页分区加载；某一分区慢或失败不会锁住整页。
- 背包/装扮对每件 badge 使用自身真实预览资源，覆盖图片型、CSS 型、WebP 和 GIF，不把不同物品显示成同一占位图。
- 上传书籍管理使用紧凑 2/3/4 列卡片，保留封面、书名、作者，不把管理页做成全屏封面预览。
- 访问其他用户时，公开资料、作品、评论、书评、动态和签到统计按独立状态加载，页面可重试并保持正常返回。

## 阅读器：App 最重要、与网页差异最大的部分

- 正文由原生阅读器承载，不需要“打开网页正文”作为阅读主流程。
- 支持连续滚动、无限滚动和分页阅读；章节末尾可自动进入下一章，分页时也能从下一章返回上一章末尾。
- 无限滚动中保持 **正文 → 章节评论 → 下一章正文** 的顺序，跨章后底栏标题和进度跟随当前可见章节更新。
- 中央单击显示/隐藏控制栏；再点正文即可隐藏，不要求双击，也不会在滚动时自动弹出。
- 可调整字体、字号、行距、段距、边距、背景、主题、亮度、图片显示和全屏，并保存偏好。
- 支持正文查找/全文替换、目录跳章、上/下一章、无动画/淡入/覆盖/滑动/仿真翻页动画。
- 音量键翻页可以单独关闭，关闭后交还系统音量；听书入口也可完全关闭而不是仅变灰。
- 正文图片支持长按原图预览、缩放、拖动、双击复原，且能够显示 GIF、WebP 与原图内层内容。

## 原生下载：网页下载 UI 被有意替换

- EPUB 与 TXT 都从 App 直接生成并保存到 Android 下载目录，不会把用户跳回网站下载页。
- 下载前可选 2/4/8/12/16 路图片并发，也支持自定义正整数；这是实际下载器参数，不只是界面装饰。
- EPUB 按章节写入目录、封面、导航、正文和插图；正文图片保留原始字节和媒体类型，不因 App 打包而压缩画质。
- 同一图片在源正文中多次出现时，仍按出现位置写入 EPUB；封面独立处理，避免“图片数量不对”或无意义重复插图。
- 大书先在私有临时文件中生成，完整校验后再发布；支持进度、暂停、继续、取消、失败原因和重试，取消后清理本轮临时文件。

## 图片与性能：为手机而做的差异

- 封面和正文插图采用统一长按预览规则：必须稳定长按，滑动超过触控阈值就取消，防止浏览书架时频繁误触。
- 预览不是缩略图放大：会请求源资源，可显示幻影坦克的内层图和动图帧，预览底部也不会被系统栏裁切。
- 搜索/收藏高图滚动减少过量预取，避免网络请求、图片解码、GC 和 Compose 绘制同时抢主线程。
- 对 360dp 小屏、软键盘关闭、长标签和卡片指标做过专门适配，优先保证可读性和操作区完整。

## 网站中仍未被 App 1:1 原生化的内容

这部分会明确保留网页回退，而不是假装“全部已经原生”。

1. **登录、注册、找回密码与 Cloudflare/安全验证**：使用保留会话的网页验证页。App 负责同步成功后的会话，不会自动绕过验证、代填验证码或读取/保存浏览器 Cookie。
2. **未识别的网页路由和低频页面**：核心路由（收藏、搜索、帖子、用户、消息、工作区、上传、书籍、阅读器、书籍编辑和已授权的管理页）有原生入口；未知、旧版或源站新增的 URL 会明确走 WebView 回退，不承诺被伪装成原生页面。
3. **网页的完整桌面版排版与所有实验性/低频表单**：App 不复制桌面 hover、复杂多栏布局、每一个 JavaScript 小组件或每种临时管理表单。遇到这类场景可通过“打开网页”继续使用源站功能。
4. **任意自定义 HTML/CSS/JavaScript 的等价渲染**：App 原生支持常见格式、黑幕、fold、链接、书卡和图片；非常规自定义标签、浏览器插件式控件或依赖站点脚本的互动，不承诺与网页逐像素一致。
5. **第三方书源、抓取规则、Legado 式规则编辑、绕过权限下载**：这是刻意不加入的能力。App 只服务 NovalPie 源站和其当前账号权限。
6. **TTS 的实际发声能力**：读取控制在 App 内，但播放、暂停和跨段朗读依赖设备已安装并启用 Android TTS 引擎；没有系统引擎时只能提示并跳转系统设置。

## 为什么保留网页回退

网页回退不是把整套 App 又变回 WebView，而是给源站变化和极少数复杂页面留出可靠出口。阅读、书架、搜索、详情、论坛、评论、个人资料、原生下载与核心管理入口仍优先使用 App；只有当前无法可靠原生承载的认证、未知路由或复杂网页专属功能才会打开源站页面。

## 安装与升级

1. 下载 `NovalPie-native-2.0.0-beta5-debug.apk` 后允许当前来源安装。
2. 覆盖安装同一 Debug 签名可以保留登录态、阅读进度、收藏设置和下载文件；若系统提示签名不一致，请先备份需要的数据，不要直接卸载旧版。
3. 遇到 Cloudflare/安全验证时，在 App 的网页回退页完成验证后回到原生页面刷新。
4. 模拟器使用本地代理时可执行 `adb reverse tcp:7890 tcp:7890`；真实手机应在 App 设置中填写实际可访问的代理地址。
