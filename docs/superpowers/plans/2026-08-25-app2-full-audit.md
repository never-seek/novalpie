# NovalPie App 2.0 全量回归审计计划

日期：2026-08-25
工程根目录：`D:\NovalPie\native-android`
目标：逐条复核 App 2.0 完成后用户提出的功能意见，以当前 canonical source、源站接口契约、自动化测试和 MuMu 运行证据为准；发现不符合要求的项目就修复，不能仅以历史文档中的“已修复”作为结论。

## 保护边界

- 不清除或迁移登录态、Cookie、收藏、阅读进度、积分、缓存和下载。
- 不读取或导出账号密码、浏览器 Cookie/token。
- 不执行 `git reset`、`checkout`、广泛删除、提交/推送或 GitHub Release 操作。
- 仅在 `native-android` canonical source 中实现本轮修复；保留已有未提交改动，逐文件核对冲突。

## 审计矩阵

### A. 论坛、书评、章节评论

- 根评论与“回复的回复”必须使用线程根 `comment_id`，同时保留被回复人的 `reply_to_name`。
- 回复失败必须保留草稿和目标，成功后刷新不能清掉刚显示的线程。
- 论坛、书籍详情书评、章节评论统一检查：Markdown/HTML、fold、剧透黑幕、链接、图片、动态图片、`[bookid:id]` 卡片、点赞/点踩/表情/打赏。

### B. 阅读器

- 分页前后章、返回上一章末尾、无限滚动与章节评论、目录/工具栏状态、听书、全文替换、翻页动画（含无动画）、音量键开关。
- 检查系统返回、重复工具按钮、控制器显示/隐藏和横竖屏/小屏安全区。

### C. 下载

- 原生 EPUB/TXT、并发/自定义并发、图片数量与重复占位符、动态图/大图、失败恢复与进度。
- 下载必须走 app 原生任务与系统文件保存，不回跳网页；验证不产生重复插图。

### D. 搜索、收藏、详情、封面

- 默认结果、成人/来源/规则筛选、完整 tag、卡片底部对齐和 2/3/4 列。
- 阅读进度和更新后章节数；封面外层/原图/动态图/幻影坦克与长按预览安全区。

### E. 我的与公开个人主页

- 动态、上传书籍、签到、背包 badge 原图预览、头像框位置、管理员权限可见性、公开主页完整数据。

### F. 导航、网络、性能与适配

- A→B→A 返回栈和旧页面污染、误触/双击、输入法空白、代理/登录恢复、安全验证白屏。
- 图片预取/缓存、列表滚动掉帧、加载态/错误态和小屏文字裁切。

## 执行顺序与验收

1. 先用失败测试锁定嵌套回复契约，再修复并覆盖根评论、子回复、祖先分页缺失三种情况。
2. 按 A-F 对当前实现逐项查源码、现有测试和历史运行证据；历史证据过期或对应代码已回归时重新验证。
3. 每个修复补最小回归测试；完成后执行 `:app:testDebugUnitTest`、`:app:testReleaseUnitTest`（可用缓存范围内）、`:app:lintDebug`、`:app:assembleDebug` 和 `git diff --check`。
4. MuMu 只用 `adb install -r` 和必要的 `adb reverse tcp:7890 tcp:7890`，不清数据；保留截图、logcat、测试结果和未验证限制。
5. 只有源码、自动化测试和运行证据都对应当前 commit 时，才把条目标记为已修复；否则明确标记为待用户验证/环境阻塞。

## 当前首个缺陷

`NovalPieViewModel.replyToForumComment()` 当前直接把 `ForumComment.id` 写入 `replyingToCommentId`。对嵌套回复，这会把子回复 ID发送为 `comment_id`。修复应沿 `parentCommentId` 链找到当前可见数据中的线程根；如果祖先不在分页窗口，安全使用已知 parent/root fallback，同时保留 `replyingToName`。
