# 2026-10-16 历史页同步状态与更新章数

## 用户反馈与复现

1601 版 MuMu 与用户截图一致：历史已加载 53 条，概览仍显示“待同步 / 收藏 — / 总页数 —”；一本书进度为 `141/147`，却显示“更新 43 章”。

两个原因独立：

1. 概览始终用收藏总数判断是否同步，并取收藏的总页数，没有使用活动的历史页状态。
2. 更新章数计算的是 `147 - 104 = 43`（旧追平目录规模），而不是扣除已经在其他设备读到的 141。直接把旧目录规模改成当前已读又会丢失“曾经追平”的证据，造成部分续读时提醒消失。

## 修复

- 概览按活动页的请求结果显示“同步中 / 已同步 / 同步失败”，未登录仍显示“未同步”。历史页显示“阅读历史 / 记录 / 历史总页数”，不再拿未加载的收藏信息冒充同步失败。
- 进度和更新标记使用同一本书的本机/远端最大已读位置。`141/147` 对应 6 个剩余新章；继续读到 `145/147` 为 2，`147/147` 清除标记，新增到 148 章后重新提示 1。
- 新增独立的本地 `completedCatalogueSize`，保存已确认追平的目录规模；`chapterCountAtLastRead` 继续作为当次观察到的目录规模，不再混用为未读位置。
- 老数据只在原有“已读章序 >= 当时目录规模”证据成立时推导追平标记，不改章节、段落断点和最近阅读顺序。普通暂停/从未读过的书不凭空生成“更新”提醒。清除单书时同步清除其新标记，不污染别的书。
- 没有远端章节 ID 时仍可用真实章序更新卡片数字，但不会伪造可跳转章节或覆盖更精确的本机段落断点。
